# Примеры использования

Этот файл показывает, как формулировать запросы к локальному агенту и как проверять, что Supervisor выбрал правильный источник.

## 1. Вопрос только по Obsidian

Откройте Gradio и задайте:

```text
Что я записал о проекте Atlas? Используй только мои заметки Obsidian.
```

В этом сценарии должен работать `obsidian_expert`. Ответ должен опираться на фрагменты с маркерами `[OBSIDIAN-N]`. Если в vault нет подходящей заметки, агент должен сказать об отсутствии данных, а не заменять ответ догадкой.

Другие варианты:

```text
Какие архитектурные решения я принял для локального RAG?

Найди в моих заметках все упоминания о миграции с FAISS.

Составь краткий список моих незавершённых задач по теме агентных систем.
```

## 2. Вопрос только по интернету

```text
Проверь актуальную документацию LangGraph по созданию StateGraph и дай ссылки на источники.
```

В этом сценарии Supervisor должен выбрать `web_researcher`. Внешние сведения должны сопровождаться URL. Если страница не открылась, это должно быть явно указано в ответе.

Примеры:

```text
Найди текущую документацию Gradio по streaming-ответам и сравни её с нашей реализацией.

Какая сейчас официальная рекомендация по интеграции LangGraph и Memanto?

Проверь, изменилась ли API-инструкция Ollama по embeddings.
```

## 3. Смешанный запрос: заметки плюс интернет

```text
Сравни мои заметки о production RAG с актуальной документацией LangGraph.\n\nРаздели ответ на: мои записи, внешние источники и вывод.
```

Здесь полезны оба агента. `obsidian_expert` извлекает локальные утверждения, а `web_researcher` проверяет внешний контекст. В финальном ответе нельзя смешивать эти два типа доказательств.

Ещё один пример:

```text
Какие идеи из моих заметок об агентной памяти уже реализованы в проекте, а какие стоит проверить по актуальной документации? Приведи источники.
```

## 4. Проверка противоречий

```text
В моих заметках указано одно, а актуальная документация может говорить иначе. Найди противоречия, покажи оба источника и не выбирай сторону без объяснения.
```

Такой запрос полезен для проверки того, что агент не превращает уверенность модели в доказательство. Для критичных решений перепроверяйте URL и исходный Markdown вручную.

## 5. Работа с сессиями в Gradio

Поле `ID сессии` позволяет разделять контекст разговоров. Например:

```text
ID сессии: research-rag
Запрос: Что я уже знаю о hybrid search?

ID сессии: research-rag
Запрос: Теперь сравни это с актуальными подходами RRF.
```

Вторая реплика использует состояние той же ветки LangGraph. Для нового независимого разговора укажите другой ID, например `project-atlas`.

## 6. CLI-вариант

Если Gradio не нужен, запустите:

```bash
python -m src.main
```

Пример диалога:

```text
Вы: /reindex
Переиндексировано фрагментов: 42

Вы: Что в заметках сказано о LangGraph?
Агент: ...

Вы: /exit
```

## 7. Программный вызов компонентов

Индекс и агент можно использовать из Python-кода:

```python
from dotenv import load_dotenv

from src.agent import create_agent
from src.config import Settings
from src.indexer import ObsidianIndex

load_dotenv()
settings = Settings.from_env()
settings.validate_vault()
index = ObsidianIndex(settings)
index.load_or_build()
agent = create_agent(settings, index)

answer = agent.invoke(
    "Что мои заметки говорят о тестировании RAG?",
    thread_id="example-session",
)
print(answer)
```

Для потоковой выдачи:

```python
for chunk in agent.stream(
    "Сравни мои заметки о RAG с внешними источниками",
    thread_id="example-session",
):
    print(chunk, end="", flush=True)
```

## 8. Правила хорошего запроса

Чем точнее разделены источник и задача, тем надёжнее маршрутизация. Для личных фактов используйте формулировку «только мои заметки». Для актуальности просите «проверь веб-источники и приведи URL». Для сравнений явно требуйте разделы «Obsidian», «Веб» и «Вывод».
